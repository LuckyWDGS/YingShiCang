# 播放控制层布局与暂停样式

版本：0.1.54-alpha / versionCode 55。范围为 TV 点播全屏控制层，按用户提供的四张影视仓截图调整，保留已有播放计时。

## 功能取舍与布局

| 位置 | 功能 | 处理理由 |
| --- | --- | --- |
| 底部横向按钮 | 下集、上集、刷新、重播、选集、倍速、片头、片尾 | 看剧时直接使用；倍速和跳过时间显示真实值 |
| 按钮下方 | 当前时间、蓝色进度条、总时长 | 复用原有计时和拖动实现，支持遥控快进与后退 |
| 固定右侧入口 | 更多 | 不必横向滚动到底才能找到 |
| 右侧更多面板 | 内核、解码、渲染、画面比例、字幕、音轨、视轨、循环、屏显 | 排成两列，将低频选项集中；按当前媒体能力显示 |
| 条件功能 | 原有弹幕、解析、版本、章节和源插件追加按钮 | 延续已有功能及处理逻辑；源插件“弹幕云搜”收进更多，不新增云服务 |
| 暂停中央 | 白色描边圆形播放图标＋当前时间 / 总时长 | 按图四改成同一行半透明面板，暂停时计时停止 |

不加入竖屏、常驻网速、迷你进度条；保留原有缓冲状态的网速提示。图二右侧系统音量面板由 Android 系统管理。清晰度选择继续隐藏，TV 按源声明自动选择最高已识别画质。

“选集”返回既有详情页并定位剧集；站源、线路固定，六列剧集独立滚动。更多打开时暂停控制层自动隐藏，遥控焦点保留在面板内；返回依次关闭更多、控制层、全屏。

## 实现与设计对应

- 图一、图二对应 `view_control_vod.xml`、`view_control_vod_action.xml` 和专用 `VodSeekView`；后者继承共享 `PlayerSeekView`，不新增计时器。
- 图三对应更多面板、实际媒体选项和遥控焦点逻辑；图四对应 `view_widget_vod.xml`、圆形播放矢量和半透明背景。
- 控制、焦点及菜单状态集中在 TV `VideoActivity`；手机、直播、投屏不采用这套新布局。
- 所有时间、倍速、内核、轨道和剧集都取自现有播放器及数据层。动态追加入口保留原监听器，移入更多；轨道、章节、解析可见性变化时重新紧凑排列。
- 以 1920×1080 雷电画面、960×540dp TV 布局适配参考。原生半透明色与渐变，无新增图片、模糊动画或轮询。菜单属于焦点与返回流程的较高风险改动，已有弹窗继续沿用原设计。

四张参考已按哈希保存在本地图片库；执行合同、交互关系、参考图和验证截图记录在 `.codex/session/`，不纳入 Git。浏览器本地文件协议受限，采用静态路径检查与原生截图比对，未将浏览器交互审查记为通过。

## 验证

- TV、手机版 ARM64 构建通过；手机版仅构建。
- 雷电 `127.0.0.2:5555` 上最终受控检查 36 项通过，覆盖播放计时推进、暂停冻结、拖动/遥控 seek、更多焦点及返回、内核/字幕/倍速弹窗、渲染与屏显开关、上下集、刷新和重播。
- 真实配置检查 19 项通过：既有历史与剧集、固定更多入口、插件按钮移入更多及遥控打开/返回、播放就绪后的动态双列排列。该样本观察到真实画面和分辨率，不能代表所有源或完整长时播放。
- 两个最终检查均恢复全部 16 个原始数据库、伴随文件及偏好文件，核验 SHA-256 和文件清单；保留 ADB 映射、移除临时工具并返回首页。安装包哈希与最终归档一致。
- 最终日志、结果和截图在 `.codex/session/qa/player-controls-v55/`；TV/手机版 APK 在 `.codex/session/releases/v55/`，交付清单为 `player-controls-v55-delivery-manifest.json`。
- 早期抓取等待、焦点和选择器排查不是全通过轮次；real02 在详情尚未填充时过早断言，修正等待条件后重测。最终结论以 final10、real04 为准。本轮未重跑与 UI 无关的 JVM 全套测试。
- 章节、版本、解析等条件入口保留原实现，本轮未逐项触发所有媒体能力。

## 维护记录

普通 UIAutomator 会等到每秒刷新的播放计时停止变化才返回，导致控制层截图失真。本轮使用独立 test-only accessibility 读取工具即时抓取 UI，不改生产包；检查后卸载。真实源还暴露出动态追加按钮与延迟轨道两种状态，因此菜单验证必须同时检查静态资源、运行时注入和播放准备完成后的变化。

下一步验证范围若扩展到新设备，应关注遥控焦点、不同分辨率下的菜单滚动和长时间播放；本轮不宣称低性能设备帧率、手机版交互或所有外部源均可播放。

# 卡片统一与短剧加载修复（v43）

2026-10-14；0.1.42-alpha / versionCode 43。

## 结果

- 按用户指定的历史卡片统一主页、分类和搜索：3:4 海报、独立 36dp 居中片名栏、单行省略、原有遥控焦点。
- 历史把 `1`、`第03集` 显示为 `第1集`、`第3集`，保留特别篇等真实名称。左上角显示按原始站源 key 解析的站名；未解析到时显示原始 key，不借用其他站源。
- 主页与分类显示真实评分，豆瓣卡片标记“豆瓣推荐”；搜索显示总集数、更新进度或当前集数。没有对应数据就隐藏标签。
- 八个分类都恢复历史、直播、搜索、配置、线路、收藏、推送、设置快捷行。原有条件性直播入口、筛选展开/收起、返回行为保留。
- AI 原生默认/最新列表独立于网页题材元数据。题材失败时保留可用的原生列表并给出题材重试；重试只补题材，不跳过下一页。保存的非空题材仍需真实元数据与对应请求，不以无关列表替代。

## 故障证据

同一模拟器、同一真实 AiDj 插件，只令用于网页题材的 HTTP client 受控失败；原生接口仍正常。

| 场景 | v42 | v43 |
| --- | --- | --- |
| 保存“最新”后冷加载，题材失败 | 0 条，加载失败 | 18 条原生最新内容；独立题材失败状态 |
| 默认列表成功，题材失败 | 18 条但误报列表失败 | 18 条，列表成功，题材单独重试 |
| 恢复网络并重试题材 | 默认列表推进到第2页，下一页变为3 | 保留18条，下一页仍为2 |

失败不写元数据缓存；继续保留严格插件识别、配置签名、选择隔离、取消与请求时限。元数据恢复若改变实际查询，先清旧查询卡片再请求新查询，避免错配标签。

## 验证

- TV/mobile ARM64 debug 构建通过；221 项 JVM 测试 / 32 套，0 失败、错误、跳过；XML 资源编译及 diff 检查通过。
- 真实 TV 界面 52 项检查通过：卡片独立底栏、评分/集数/站源、遥控焦点、全部分类快捷行、筛选重复点击与 Back、真实搜索到详情及返回。
- 真实 AI 5 个场景均有内容：冷加载默认、最新、脑洞题材、另一 AI 类型、保存题材后冷启动；未宣称覆盖全部题材。
- 最终安装 TV 包 SHA-256 与交付包一致。每个有效诊断/验收轮次恢复13个原数据库及偏好文件，SHA-256 和文件清单校验通过；测试包移除，ADB 映射保持，最终回到主页。
- 用户卡片/快捷行原图已持久保存并校验。逐区域核对海报、底栏、站源、元信息和快捷行；海报/时间变化不使用全屏像素误差作门槛。

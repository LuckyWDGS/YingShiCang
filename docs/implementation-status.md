# 实施记录

当前为开发中的 Alpha，尚未完成计划书全部功能；所有安装测试仅针对 `emulator-5580`，实体设备未安装。

## 源码与构建

- 原仓库只有 README；导入 FongMi/TV 作为候选兼容内核。
- 最新 TV 源码依赖未公开配套的 libass 接口；目前选择 `fe6a5b235477c02633cf3bc50d4cd83414a521b4` 的 app 源码，与 FongMi/media `3c2cbe8ac742c2fe15eff52f03eeb3b1b648848d` 的 1.11.0 分支编译。
- 当前 Gradle 9.1.0 / AGP 9.0.1 / Java 21 / compileSdk 37 / targetSdk 36 / minSdk 24。compileSdk 37 超出该 AGP 官方测试范围，已知警告待统一依赖版本后处理。
- Python 构建依赖 3.10；已安装到用户目录，不能使用系统 Python 3.12 替代该依赖。
- 媒体复合构建当前引用本机依赖目录，尚需整理为可复现的依赖获取脚本；不能宣称干净克隆已可直接构建。

## 测试基线

- 原影视仓 6.2.0：模拟器安装成功，但启动时在 ARM32 翻译层发生 native SIGSEGV，未能进入原版功能测试。
- 新版第一轮 ARM64：模拟器启动成功，饭太硬源导入成功；聚合搜索时发生 `libndk_translation.so` SIMD 指令 SIGILL。该现象不能直接当作用户电视上的夸克崩溃根因。
- 下一步补充原生 x86_64 构建以剥离模拟器 ARM 翻译层问题，再验证真实源、播放器及维护页。
- 首批日志和评分 JVM 测试通过；后续新增维护功能仍在构建和回归。

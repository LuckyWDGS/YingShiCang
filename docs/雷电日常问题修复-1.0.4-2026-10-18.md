# 雷电日常使用问题修复验证（1.0.4）

本轮修复 1.0.3 日常使用测试发现的直接重试、空匹配连续扫描、历史返回焦点和分类返回行为问题。版本 1.0.4 / code 60，沿用原正式签名；仅本地交付。

后续覆盖说明（本地 1.0.9）：用户要求移除有片单时“部分站源加载失败，已保留当前结果”和右侧“重试”整条提示。当前实现已隐藏该部分失败行，保留后台限次重试和失败页游标；扫描暂停时仅显示独立“继续查找”，空列表失败仍可重试。下文双按钮记录是 1.0.4 的历史测试结果。

## 行为修改

- 失败状态增加可遥控聚焦的“重试”。仅重发失败来源的原始页，保留已有片单；每次手动操作之后的自动重试仍最多两次。
- 连续三个聚合轮次没有新增可见卡片时暂停自动扫描，显示“继续查找”；继续沿原始游标请求，不重新从第一页开始。每个聚合轮次可能包含多个来源，不等于全局仅请求三页。
- 失败重试不消耗健康来源的空扫描预算。失败与暂停并存时，同时保留“重试”和“继续查找”，健康来源仍能继续翻页。
- 历史复用列表与卡片适配器，返回时按完整历史身份定位。最近播放导致排序变化时仍定位同一影片；用户导航、按键和触摸会取消待执行的焦点恢复。尺寸设置变化后按需重建，离开历史和空历史清除删除模式。
- 非首页分类按返回键，在关闭筛选、结束历史删除等既有步骤之后统一回主页；主页继续使用原退出行为。

## 雷电验证

使用上述最终正式签名 ARM64 包，覆盖安装到已验证的本地雷电 Android 14 / API 34，x86_64 + ARM 转译。测试期间关键源码与打包快照一致。

| 场景 | 实测结果 |
| --- | --- |
| 八个非首页分类 | 稳定片单顶部 Back 回主页；重复点击打开筛选，首 Back 关闭筛选且留在分类，下一次 Back 回主页。40 项通过。 |
| 历史详情返回 | 首张、第三张和实际滚动后的后排替代影片，分别进入真实详情并 Back，焦点均保留原片名与来源；历史 Back、主页退出及重新打开通过。历史主流程按分段证据完成，共 54 个不同检查名。 |
| 历史日常操作 | 遥控长按进入删除，首 Back 退出且历史保留；删除模式切分类后不残留；实际改变卡片尺寸后历史更新，恢复尺寸后回到原大小。12 项通过。 |
| 连续空匹配 | 单源只请求原始页 1、2、3 后暂停；无输入不继续。遥控“继续查找”只继续 4、5、6，再次暂停。 |
| 失败直接重试 | 首次请求及两次自动重试后停止；服务恢复后遥控“重试”从失败原页恢复，已有成功来源片单保留，耗尽的成功来源不重发。 |
| 分类切换取消 | 旧电影延迟请求被取消，电视仍选中且显示正确电视结果，没有旧分类续页污染。基础受控与补测合并为 21 项有效检查。 |
| 健康源与第 2 页故障源混合 | 故障源第 2 页原位重试，明确看到恢复影片；旧片单保留、健康源原始游标继续前进；实际遥控滚动后一次 Back 回主页。14 项通过。 |
| 失败与空扫描暂停并存 | 自动失败重试不消耗健康源扫描额度；健康源 2～4 页连续无匹配才暂停，两个按钮同时可遥控到达；继续只推进健康源 5～7 页，保留首张卡片且不重试故障源。16 项通过。 |

分段证据保留了测试脚本的中断及修正：首次全局加载态 Back 按既有优先级收起加载层；历史脚本的旧焦点目标/已聚焦节点返回值、混合测试对裁切卡片的辅助聚焦均已修正后补测。取消测试初版把电视数据误标“电影”，被产品正确过滤；修正 fixture 后四项补测通过。中断的整轮不记为完整通过。

边界：全局加载层仍先消费一次 Back；本轮未改变此优先级。原先选中的一张后排历史卡片因真实来源未提供详情，单列跳过，再用可用的后排影片完成焦点验证。本轮没有动态建立“最近观看时间导致排序改变”的场景，也未触发后台 HISTORY 事件；这两项只有代码路径审查。没有实体机、全部来源、长时播放或帧性能结论。

## 内存调查

上轮 PSS 上涨缺少固定缓存、数据和基线条件，不能据此确定泄漏。本轮静态审查未发现足以支持修改的 Activity 保留链；没有猜测性修改缓存上限或插件 Context。

受控实验使用同一配置、电影/电视各固定 20 个 ID、无海报、各仅一页；每次响应内容 SHA 一致。先预热 10 轮，再做三组各 20 轮“电影→电视→电影”，每次在相同电影页静置 3 秒采样，最后再静置 30 秒。未强制 GC。

固定 HTTP 分类场景没有复现持续上涨，对象计数也未增加。该结果不能代替真实第三方插件、图片缓存或长时播放的堆保留链验证，不能据此宣布全部场景不存在泄漏。静态及本轮采样没有确认可修复的泄漏根因，内存问题保留为观察项。

分项中 Java 已分配堆为 4551→4683→4685→4690→4549 KiB，Native 已分配堆为 26984→30804→29842→29418→25930 KiB，也均在末次回落。PSS 波动主要涉及 `Unknown` 与 `.so mmap`，没有收集能确定其回落根因的堆/原生分配追踪。此模拟器的 Native/Dalvik PSS 与 Graphics 分类为零，即使已分配堆非零，不能按该零值声称没有相关占用。

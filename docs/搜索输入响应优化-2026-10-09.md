# 搜索输入响应优化

版本：0.1.26-alpha / versionCode 27。TV已安装到授权模拟器，手机版仅构建。

用户反馈：输入一个汉字或字母就出现提示，体感慢。范围仅为 TV 搜索页输入、可选联想和提交，沿用既有黑色三列布局、历史、键盘及结果卡片。截图是问题现场，不是新设计；本轮无需生成视觉参考。

## 行为与实现

| 场景 | 实现与数据 | 交互与验证 |
| --- | --- | --- |
| 输入字符 | CustomKeyboard 直接修改 Editable，现有255长度过滤生效 | 连续按键、选区替换、Unicode退格；保持按键布局 |
| 非空输入等待联想 | 不显示加载、无结果或不可用提示；旧词隐藏，不逐键清空 adapter | 单字母、连续输入；输入与正式搜索始终可用 |
| 联想请求 | 实际 iqiyi 联想接口；150ms防抖、Call总超时3秒；解析与转换在后台；去空/去重、最多24项 | 确定性取消与过期回调测试；真实服务速度不作保证 |
| 重复/退格输入 | 页面内32项LRU缓存，5分钟有效期，不写磁盘；失败不缓存 | 命中即时交付，TTL和容量测试 |
| 新联想显示 | 输入版本、生命周期校验，并等待AsyncListDiffer提交 | 防止旧查询/隐藏页面结果显示 |
| 搜索/离开/返回 | 非空内容包括单字/字母直接提交；先取消联想，返回按当前词恢复 | 正式搜索、历史、返回、清空后晚到结果检查 |
| 空输入 | 现有热门榜单、加载/部分失败状态；空内容提交保持原提示 | 清空恢复榜单 |

UI属于既有页面的低风险行内变更；异步交付/缓存属于中风险逻辑，单独测试。未改v26站源池、电影/电视全站源筛选和18+隔离。

## 验收

- TV/mobile arm64 debug构建通过，完整109项JVM测试0失败/错误/跳过；其中新增16项控制器测试覆盖快速输入、旧回调、取消时同步回调、关闭/恢复、缓存及瞬时失败。构建日志：.codex/session/search-input-build-v27.log。
- v26对照和v27验收各11项通过，覆盖单A、连续ABC、删除、清空、长按删除、单字符正式搜索/两站源正确结果、返回首页、空崩溃缓冲和数据恢复。证据：.codex/session/qa/search-input-baseline-v26和search-input-optimized-v27。旧版即时A截图复现“正在获取关键词…”，新版截图及非空输入界面树没有联想提示。
- 模拟器验收只允许127.0.0.1:5555；测试数据是隔离脚本内的文本标签，未加入运行时。原配置DB和全部偏好在验收后恢复并核对SHA256。
- 中文单字通过已有UTF-8远程搜索入口验证语义，不能替代中文输入法逐键覆盖。真实联想网络无确定性拦截；超时/旧回调由单测及代码审查补充。
- 输入按键命令耗时A两版均0.047秒；连续ABC旧0.125秒/新0.141秒，不能证明逐帧输入提速。单A正式搜索请求发出旧0.140秒/新0.125秒，首卡观测上界两版均4.375秒。这里验证了直接提交和提示移除，不宣称本轮普通结果查询更快。UIAutomator时间包括抓树，不能当成帧时延。
- 中文输入法、选区替换/代理对退格的设备覆盖、手机版运行和真实插件时延未新增验证；选区和代理对逻辑已代码审查。下一步验证目标是实际TV输入帧时间和中文输入法，只有出现具体问题才扩展当前范围。
- 截图预览工具曾显示不完整差分；原PNG像素统计和独立新截图正常，未据工具显示异常修改应用渲染。

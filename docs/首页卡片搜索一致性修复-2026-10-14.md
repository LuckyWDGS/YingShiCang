# 首页卡片搜索一致性修复

日期：2026-10-14。影视仓+ 0.1.36-alpha / versionCode 37。

点击首页推荐卡片后，聚合结果现在携带所选影片的标题和年份，过滤无关标题、明确不同年份及不同季数，优先显示精确匹配。真实站源卡片继续按自身站源与影片 ID 进入详情；手动输入搜索保留宽泛结果和渐进展示。

## 原因与原版对照

豆瓣推荐只有索引 ID，没有真实站源影片身份，必须通过标题找到资源。原先聚合结果按站源回包顺序展示，快源的无关结果或同名不同年份内容容易先出现。搜索页重建时，保留的 ViewModel 还可能重放上一轮结果；异步重排也需要保护当前焦点的影片身份。

已对原影视仓 6.2.0 APK 做主机 DEX 静态审查，样本 SHA-256 为 fd1b68f2eb7c9b02b2fb08069e6ad6476450a70514f970e496e499c73f7632db：真实卡片传自身 sourceKey/id 进入详情，无真实 ID 或 msearch 卡片按标题进入 FastSearch；正式结果要求名称包含全部关键词；点击结果继续传该结果自身的站源和 ID。年份、季数、稳定卡片 ID 和生命周期隔离属于本轮加强。原 HomeActivity 部分方法为 NATIVE，未对缺失实现作推测。完整指令证据在本地 .codex/session/research/card-route-20261014/MECHANISM.md；FongMi 源码参考与原 APK 证据分别记录。

## 修改

- SearchResultRanker：归一简繁体、标点、大小写、全角及第二季/第2季/S02/Season 2。原作不接受明确续作；保留国语、高清版、4K/1080p。合法独立年份装饰在年份字段缺失时参与核对；纯数字作品名不被当作年份。缺少年份仍可候选，已知错年拒绝。
- CollectActivity：区分卡片搜索与手动搜索，缓存每个原始资源的匹配分数并稳定排序。用站源+影片 ID 分配稳定卡片身份，晚到结果插入后保持当前焦点及确认键目标。过滤后的原始身份仍用于分页，连续无新增匹配页最多自动扫描3页，可点击来源继续。真实空结果给出匹配说明。
- SiteViewModel：仅结果页调用 resetSearch 清理保留的上一轮批次及状态，保留请求取消和代际隔离；播放页快速搜索不收到新增 null 清空事件。
- HomeActivity、TypeFragment：卡片入口传标题/年份，真实站源详情保留原始身份。

沿用现有五列卡片、侧栏、导航和视觉样式，没有新增设计参考或演示数据。主要风险是异步状态、焦点和站源元数据，验证覆盖这些分支。

测试用纯文本 localhost fixture，未向运行时产品写入演示站源或内容。推荐卡测试构造卡片并调用实际 Home 点击入口；不等同于验证真实豆瓣网络取卡、全部外部站源可用性或影片播放。上游标题或年份错误仍可能影响匹配。

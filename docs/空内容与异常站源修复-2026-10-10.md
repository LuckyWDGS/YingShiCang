# 空内容与异常站源排查和修复

日期：2026-10-10。项目：影视仓+；交付版本：0.1.33-alpha / code 34。

## 本次范围

实际配置有 48 个 type3 站源，其中 31 个开启搜索，17 个明确关闭。开启源按现有配置参与，关闭源保持关闭。测试关键词为三体、流浪地球、庆余年、海贼王、短剧、英雄联盟；直播另用王者荣耀、和平精英对照。

原始插件基线覆盖 17 个问题及对照源 × 6 个关键词，之后覆盖全部 31 个开启源的 `SiteApi.searchContent`。真正无匹配的 `list:[]`、空字符串、无效响应、异常、超时、未执行分别记录。诊断工具的独立 20 秒上限与真实聚合搜索的单源 15 秒预算分别报告。

## 程序修改

1. JS 源缺少 `pdfh/pdfa/pd` 时使用项目现有 cheerio 补齐基础 HTML 解析；插件自带实现优先。当前远程 JAR 未提供相关 Function 类，实际 QuickJS 曾抛出 `pdfh is not defined`。
2. JS/JAR 只缓存成功初始化的实例；失败不会永久变成空插件。下载与模块失败可再次尝试，保留取消状态，失败资源清理放到独立的有界执行器。
3. 搜索响应严格验证 list、错误字段和有效影片身份。空串、错误 JSON、HTML 验证页等不会默默转换为“没有匹配”。真正的空列表保留；未实现的默认分页方法与已实现却返回空串的方法分别处理。
4. 新6V旧搜索接口返回 404。兼容实现从实际页面读取当前 POST 表单及字段，并解析真实结果；仅在已确认 SixV 插件的首屏为空时启用，共享原搜索期限和取消。返回相对详情 ID，继续调用原插件详情与播放方法。
5. AI短漫剧的 Java/Python 桥先检查宿主包名，再按 `packageName + ".App"` 反射。本应用更名后，插件在反射前提前退出，所以 Python 字段全部为空；仅补反射入口不足以恢复。兼容处理限定于已审计的 AiDj/oE 初始化，保留实际应用存储、配置和其它上下文行为，并在后台准备项目 Android Python 平台。最终实测结果见下文。

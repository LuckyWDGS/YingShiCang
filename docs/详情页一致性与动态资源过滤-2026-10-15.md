# 详情页一致性与动态资源过滤

版本：0.1.48-alpha / versionCode 49。平台：Android TV；mobile 同步共用逻辑并构建。

## 交互与布局

采用影视仓 `detail3` 参考的结构：左侧预览、右侧资料，下方线路和六列选集。资料按标题、来源/年份/地区/类型、演员、导演、当前播放地址、三行简介排列；缺失字段隐藏，长字段省略，完整简介可单独打开。四个按钮依次为「快速搜索、倒序、加入收藏、内容简介」。保留用户已确认的黑色影院配色、原生遥控焦点和全屏/返回逻辑。

设计实施契约见 [详情页与选集体验重设计](详情页与选集体验重设计-2026-10-14.md)。本次没有新增图片或字体；沿用已有播放器、简介弹窗、收藏和排序处理器。实际来源数据填充资料，不向产品加入测试片单。

## 动态过滤规则

| 观察结果 | 行为 |
| --- | --- |
| 同一次详情加载连续两次返回结构有效的空详情/空播放列表 | 暂时隐藏这条搜索结果 |
| 来源明确返回资源不存在、下架、分享取消或失效 | 暂时隐藏对应资源；播放阶段仍按集数/线路确认 |
| 超时、DNS/TLS、连接、鉴权、验证码、限流、服务故障，普通 HTTP 404/410 | 当作临时问题，不加入资源过滤记录 |
| 先网络失败，重试后仅有一次有效空详情 | 证据不足，不隐藏 |
| 单集或单条线路确认失效 | 只记录该集/线路；全部可播放候选都确认失效才隐藏整部 |
| 后续成功获取详情或实际播放成功 | 恢复对应资源可见性 |

记录仅在本机内存，按配置版本、站源和资源 ID 隔离，使用单调时钟，30 分钟到期；重启清空。不同用户互不影响，不保存永久黑名单，不更改站源启用状态。到期后的重新展示/新搜索会重新评估；不会后台逐条预播放整个搜索列表。

JSON/XML 先检查结构，再解析详情和播放结果。HTML 验证页、坏 JSON、未知结构、内部播放列表提取异常不会伪装成空资源。详情最多静默重试一次，两次请求共用原有 30 秒总时限；搜索沿用有界自动重试，无新增重试按钮。

## 异步和候选列表

- 旧详情、播放、预加载回调受 generation、配置版本和请求身份约束；通用播放器错误缺少请求身份，不用于资源屏蔽。
- 搜索结果保留原始分页身份，显示层再过滤；即使当前页均被过滤或仅有文件夹，仍能推进后续页。过滤到期保留恢复机会。
- 自动换源候选按站源＋资源 ID 去重并累积分批结果；一轮自动搜索后等待后续批次，避免循环重搜。
- 手动选集、线路、来源、清晰度或刷新后，迟到的搜索结果只更新候选，不打断新选择。新选择失败时仍可继续换源。
- TV/mobile 快速候选适配器按快照差量更新；已消耗候选移除，未改变的项不重复插入。

## 验证边界

隔离 HTTP/视频 fixture 用于复现暂时故障、空数据、明确失效、跨源同 ID 和延迟回调，不能证明外部所有站源当前可用。真实配置另行验证详情与导航路径。Mobile 本轮只构建，没有手机交互验证。

后续维护应继续区分「明确资源证据」和「当前环境失败」，避免扩大错误字符串匹配范围。设备诊断快照必须枚举所有数据库和偏好文件，不能只假定存在主数据库；QA 中的 UI 查询使用完整 app resource-id，避免匹配系统同名节点。
